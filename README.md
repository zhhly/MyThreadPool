# 手动实现Java线程池：

  - 池化技术：资源管理优化策略。
    核心思想是：预先创建一批资源对象放入“池”中，需要时从池中获取，用完后归还，避免频繁创建和销毁。

  - 线程池的实现：
    首先，我们假设池子里面只有一个线程。那么任务来了就创建线程去执行。
    如果任务忙不过来呢？多创建几个线程去执行任务。

    那么线程放哪呢？放队列里面。一开始使用List当作线程队列，但是这里有个问题。一直没任务过来那不是一直占用着CPU资源？
    当任务空的时候有没有其他的队列可以不占用CPU资源从而进行阻塞呢？BlockingQueue阻塞队列可以做到。

    但是，线程池要设置多少个线程呢？堵塞队列要设置多大呢？ 是不是可以通过构造方法，让用户自己传进去？ 那么可以给构造方法传入 核心的线程数量（corePoolSize）.
    但是，如果核心线程数不够用怎么办？  给他加几个辅助线程，也就是最大线程数（maxPoolSize）。

    前面说了，阻塞队列如果没任务了就会一直阻塞，那么不想让他一直阻塞要怎么办？ 可以设置等待时间，也就是 timeout. 以及时间单位，timeUnit。

    要是任务数量太多了，以至于最大线程数都执行不过来，可以还是源源不断的又任务进来怎么办？  我们设置一个拒绝策略来应对这种情况。

    在Java的线程池中拒绝策略有四种分别是：
      - AbortPolicy	：默认抛出异常
      - CallerRunsPolicy ： 再次调用线程去运行 
      - DiscardPolicy	： 什么也不做
      - DiscardOldestPolicy	：将任务丢了不去执行

     我这里只做了三种，1、抛出异常，2、再次调用线程去运行 ，3、将任务丢了不去执行。

    这样我们就完成了一个线程池基本的功能。（还没有实现showdonw功能）其实只需要判断线程执行完了没即可，执行完了就给他们都停了。
